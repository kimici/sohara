## 12:29:48 CST — sqlite subscribe 路径补齐 + zeromq Rust 实现落地

- **变更**：`sohara-builtin-sqlite` 现在除了 `builtin-sqlite-store` / `builtin-sqlite-bus`，还提供 `builtin-sqlite-trigger`，订阅模型是 **同一个 SQLite 文件上的 `event_bus` 表轮询**：bus 侧写入 topic/payload，trigger 侧按 `id` 递增拉取同 topic 记录。`sohara-builtin-zeromq` 也不再是 `bail!` 占位，已经换成真实 Rust binary，支持 `builtin-zeromq-bus` 与 `builtin-zeromq-trigger`。同时，`sohara-runtime/src/stdio_extensions.rs` 对 trigger 的空拉取做了让步处理（允许 `done=false` 且暂时无记录，短暂 sleep 后继续），避免轮询 trigger 饿死其他 source/task。
- **原因**：用户指出了两个真实缺口：zeromq 仍是 placeholder；sqlite event bus 只有 publish 没有 subscribe 语义。
- **验收**：`cargo test -p sohara-runtime --test stdio_extensions`、`cargo test -p sohara-builtin-extensions`、`cargo test -p sohara-cli`。
- **剩余**：redis/zeromq 仍缺更强的端到端环境验证与使用文档；generic `EventBus` 仍是 publish-only，builtin sqlite/zeromq 的 subscribe 是 provider-specific trigger 配对模型。

## 12:47:31 CST — generic EventBus 消费模型澄清 + builtin sqlite/zeromq 覆盖整理

- **变更**：补充并固化了当前消费模型：generic `EventBus` 仍只负责 publish；下游消费分两类——(1) built-in `queue` trigger 只消费 in-process bus；(2) provider-specific paired trigger（如 `builtin-sqlite-trigger`、`builtin-zeromq-trigger`）消费对应 backend。测试侧把 `trusted_builtin_sqlite_bus_pairs_with_builtin_trigger` 加进默认集成套件，证明 sqlite 无外部服务依赖、可直接做端到端验证；同时尝试加入 builtin zeromq bus/trigger 端到端测试，但当前纯 Rust zeromq runtime 仍不够稳定，因此该测试保留为 ignored，不纳入默认 suite。
- **原因**：用户追问 generic eventbus 如何被下游消费，以及 sqlite / zeromq 是否都能直接纳入集成测试。
- **验收**：`cargo test -p sohara-runtime --test stdio_extensions`（10 passed, 1 ignored）、`cargo test -p sohara-builtin-extensions`、`cargo test -p sohara-cli`。
- **剩余**：若要把 zeromq 也纳入默认集成测试，需要继续稳定其 runtime 行为或调整测试策略；generic bus subscribe 抽象仍未统一到 trait 层。
