## 10:46:14 CST — A1 state/checkpoint bridge 落地

- **变更**：实现 roadmap A1。`sohara-core` 新增 `StateAccessor`，`BuildContext` 新增 `state_accessor`；`sohara-runtime` 把运行态 step state 收敛为共享的单一权威状态体，脚本步骤在 build 时拿到该 accessor，`ctx.state` 直接读写 runtime 状态，`ctx.checkpoint()` 直接触发 `StateStore` flush。脚本状态恢复也已接通 `--resume`：即便脚本步骤没有声明 `node.state` 初始块，也会从 store 中恢复先前 checkpoint 的状态。`quickjs-api.md` 已同步更新。
- **原因**：继续按 roadmap 推进，补齐此前 `StepEnv.state` 与 runtime `Executor.states` / `StateStore` 脱节的问题。
- **验收**：`cargo test -p sohara-runtime --test persistence`、`cargo test -p sohara-js --test host_core`、`cargo test -p sohara-runtime --test stdio_extensions`、`cargo test -p sohara-cli`。
- **剩余**：A2 `sohara.registerStep()` 尚未开始；Phase B 的 timeout/restart/error model 也仍待收尾。

## 15:31:19 CST — A2 `sohara.registerStep()` 落地

- **变更**：实现 flow-local 的 `sohara.registerStep()`。`sohara-core` 新增 `RegisteredStep` 与 `BuildContext.registered_steps`；`sohara-config` 新增 flow 级两遍构建（先扫描所有 `type: script` 步骤收集注册，再用临时 registry 正式构建 flow）；`sohara-js` 新增 `__register_step` callback、preamble 的 `sohara.registerStep(...)`、以及 registered step factory。注册语义已更新为 **per-flow / build-time**，不再是文档里原来的“当前 context 作用域”设计稿。补了一条运行时集成测试，验证 `type: slugify` 可以在 YAML 中先使用、后由脚本注册。
- **原因**：继续按 roadmap 推进，补齐脚本动态注册步骤的核心能力。
- **验收**：`cargo test -p sohara-runtime --test script_registration`、`cargo test -p sohara-runtime --test persistence`、`cargo test -p sohara-js --test host_core`、`cargo test -p sohara-runtime --test stdio_extensions`、`cargo test -p sohara-cli`。
- **剩余**：A0a/A3 async bridge 仍未定案；接下来更大的 gap 转向 `sohara server` / flow API，以及 stdio extension 的 timeout / restart / error model 收尾。
