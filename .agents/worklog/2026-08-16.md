## 23:50 CST — 修复 CI 测试失败：file sink 写盘竞态（tokio write_all 缓冲写）

- 症状：GitHub Actions（ubuntu）与 Linux VM 上，多个「写文件后立即读回」的测试随机失败（sohara-js script.rs 与 sohara-builtins steps.rs 的 `got: ` 空文件；macOS 从不复发；修复前 Linux 复现率 ~90%）。
- 根因（LD_PRELOAD 系统调用级追踪 + tokio 源码确认）：tokio `File::poll_write` 把数据拷入内部缓冲并 spawn 阻塞池任务后**立即返回 Ready**，`write_all` 在最后一个 chunk 的 `write(2)` 仍在飞行时就返回 Ok；随后 run() 返回、测试读文件，读到的是刚被 O_TRUNC 打开的空文件（写入 280µs 后才落到页缓存）。与 QuickJS 无关，任何 file sink + 立即读都受影响。
- 修复：`FileSink::write` 在 `write_all` 后追加 `file.flush().await`（tokio `poll_flush` 会等待挂起的阻塞池写完成），保证数据真实落盘后才返回成功。
- 验证：修复后 Linux VM 上 sohara-js 与 sohara-builtins 两套测试各连跑 20 次全绿（修复前 ~90% 失败）；macOS 122 测试全绿；clippy/fmt/长度门禁通过；诊断期加入的全部调试代码已还原（diff 仅剩 6 行修复）。
